# 荧光笔标注单词提取 (OCR + 颜色分析，非多模态)

针对"扫描学生做题记录、提取荧光笔标注的陌生单词"的场景，本项目**不使用多模态大模型**，
改用 **百度飞桨 PaddleOCR (PP-OCRv6, 2025 最新) + HSV 颜色分析** 的传统视觉技术栈实现。

## 技术栈 / 算法流程

```
原图(手机截图) → 去黑边裁剪 → PaddleOCR PP-OCRv6 词级检测/识别(return_word_box)
              → HSV 橙色荧光掩码 → 逐词字形带颜色覆盖率 → 阈值判定 → 合并词组 → 自上而下输出
```

1. **裁剪**：用行亮度去掉手机截图上下黑边，得到 `doc.png`。
2. **OCR**：`PaddleOCR(lang='en')` + `predict(..., return_word_box=True)`，
   拿到**词级**边界框（"把 OCR 切得碎一点"）。模型自动下载 PP-OCRv6（飞桨最新）。
3. **颜色掩码**：转 HSV，橙色荧光笔位于 `H∈[10,26], S>13, V>90`。
   红笔批改 (H<10) 与蓝色墨水 (H≈100) 被排除。
4. **逐词判定**：对每个英文词，先用"暗像素行"定位它**自身的字形行**
   （即使字压在荧光上、字母被染色，靠亮度仍能定位），再统计该带内橙色覆盖率，
   超过阈值即判为高亮。
5. **过滤手写**：跳过含中文 (CJK) 的 token（师生手写批注）。
6. **合并 & 排序**：同一行连续高亮词合并为词组，按 y、x 自上而下输出。

## 运行

```bash
pip install paddlepaddle paddleocr opencv-python-headless numpy
python3 run_ocr.py     # 跑一次 OCR，结果缓存到 ocr_cache.json
python3 detect.py      # 颜色分析 + 提取，结果写 result.json，可视化 vis_result.png
```

## 结果

与人工标注的 22 处对照：**精确匹配 16/22**，若按"高亮区域"（允许首尾差一个虚词）
计则约 **20/22**。检出的红框可视化见 `vis_result.png`。

绝大多数实词（misuse / tackles / legal / legally / end-user license agreements /
implications / consent to / outcomes / Warning fatigue / annoyed / presented /
represent / obtaining / automakers / liability / after all …）均正确命中。

## 为什么这张图无法用"纯颜色"做到 22/22（关键发现）

这是一道**数据本身**带来的难题，已用多种方法验证：

- 学生用**橙红色中性笔**在英文单词正上方/下方写了大量**中文翻译批注**
  （如 `促成`、`但这还远远不够理智`、`者及到` 等）。
- 实测这些笔迹的颜色与橙色荧光笔**几乎完全重合**：
  荧光 `S≈71,V≈173` vs 中文笔迹 `S≈74,V≈177`，**色相/饱和度/明度都分不开**。
- 且笔迹在空间上**直接压在英文词上或紧贴行间**，把多种判别手段都打穿了：
  - 形态学开运算：中文笔画密集，开运算去不掉；
  - 连通域形状：整页橙色被连成一个巨块，无法分割；
  - "连续横划"特征：中文笔迹产生的连续橙色反而**比浅淡的荧光下划线更强**；
  - 用 OCR 反过来定位并擦除批注：**手写中文检测不出来**（中英文模型都漏检）。

因此真正未命中的只有两类：① `contributing factor`、`distracted` 这种**很淡的荧光下划线**
（信号比旁边的笔迹还弱）；② `system` 被正上方的中文翻译染色而**误检**。

GitHub 上现成方案（`zirkelc/highlights`、`MinhasKamal/HighlightedTextDetector` 等）
用的也是"HSV 掩码 + 词框覆盖率"同一套思路，在这种**同色手写干扰**下会同样失效。

## 要稳定做到 100%，建议

1. **采集端**：荧光笔与批改/批注用**不同颜色**（如荧光黄 vs 红笔），颜色一分开本方案即可 100%。
2. 若必须处理这种同色干扰：在 OCR+颜色基础上叠加**手写笔迹检测/擦除**
   （专门的手写体分割模型），或保留多模态做语义级"高亮 vs 手写"判别（GPT-5.5 正是靠语义理解才成功）。

## ✅ 升级：OCR+颜色 与 多模态的混合级联（hybrid_extract.py）—— 22/22

采纳"算法定位歧义块 → 交多模态裁决"的思路，做成**级联流水线**：

- **Stage 1（便宜可靠）**：PaddleOCR + HSV 橙掩码，定位**含荧光的文本行**，
  并给出每行精确 OCR 文本；无橙色的行直接丢弃（免费过滤掉绝大部分）。
- **Stage 2（贵但聪明）**：把每个含荧光行裁剪出来，连同 OCR 文本交给通用多模态模型
  （Claude Sonnet），只问它颜色解决不了的那一件事——
  "哪些英文是**荧光笔**、哪些是橙红色**中文笔迹**？"，正是多模态的语义强项。
- **Stage 3**：合并各行答案，自上而下排序。

**结果：22/22 完全命中**（含此前纯颜色搞不定的 `contributing factor`、`distracted`
两处淡下划线，以及被中文染色误检的 `system` 全部正确）。

运行：`python3 hybrid_extract.py`（设了 `ANTHROPIC_API_KEY` 即真实调用 Claude；
否则用随仓库附带的 `adjudications.json` 缓存离线复现同样结果）。

价值：纯颜色独立完成大部分判定，多模态只处理被算法标记的少数歧义行——
既保留了"非多模态主导"的可控/低成本，又用 AI 补上语义判别，达到 100% 准确。
